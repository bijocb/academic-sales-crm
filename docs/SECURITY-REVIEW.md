# Security review — Phase 15

Date: 2026-11-28. Scope: the whole repository at the Phase 15 commit, against SRS §8 and §8.1 (OWASP-aligned baseline).
Automated checks that keep it true: `test/security.int-spec.ts` (RLS and append-only for every table), the role and
scope tests in `test/access.int-spec.ts` and `test/rls.int-spec.ts`, `pnpm audit --prod` (release checklist).

## Controls verified

| Area                 | Control                                                                                                                                                                                                                                                                                                             | Evidence                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Authentication       | Argon2id passwords; short-lived access token and rotating refresh token in `httpOnly`, `Secure`, `SameSite` cookies; session revocation; lockout after repeated failures; password reset and invite tokens stored hashed and single-use                                                                             | `auth.service.ts`, `cookies.ts`, `test/auth.int-spec.ts`        |
| Authorization        | A global guard denies by default; only these routes skip login: health, login/refresh/reset, intake (API key), Google Ads webhook (key), payment webhook (HMAC), document download (signed token), scheduler (secret), sandbox pages (not in production)                                                            | `@Public()` audit in this review; `test/access.int-spec.ts`     |

| Out-of-scope records | 404 (no existence leak), missing permission 403, enforced in services, not the UI                                                                                                                                                                                                                                   | integration tests in every phase                                |
